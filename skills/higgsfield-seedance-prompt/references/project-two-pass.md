# Two-pass story-video project contract

Use this mode when a project needs generated references before submitting a video. Input is one approved story segment's prose and its relevant start/end continuity. Design the visible sequence first. The first-pass outputs are a standalone prompt file and `ai-video-reference-asset-request@1.0.0` JSON. Reference needs are inferred from the actual shot design, not from an upstream asset table.

The request contains `schema`, `schema_version`, `source` (story path/hash, prompt path/hash, segment ID), `shots` (stable ID, start/end seconds, visible task), and `assets`. Each asset has stable `asset_id`, exact name, `kind`, `asset_form`, purpose, brief, `consumer_shots` using shot IDs, dependencies, acceptance checks and approval requirement. Same recurring identity/space/object should keep one stable ID across segments. The project controller may maintain a project-wide ID registry. Reference requirements describe needed views or states; actual image paths appear only after production.

The first-pass draft starts with `SCENE CONTEXT` and includes at least one following prompt block such as `LOCATION MAP` or `FIRST FRAME / BLOCKING`. It leaves `ACTIVE REFERENCES` for the binding pass. The request's `source.prompt_path` and `source.prompt_sha256` identify this exact draft. Blank lines between blocks are optional.

Run `scripts/reference_request.py validate --input ...` before handoff; it checks the source files, hashes, and first-pass draft shape together. The asset studio can select `--all`, `--asset-id`, or `--asset-name`; selection is a runtime choice, so the request stays immutable. The schema validator also accepts the prior 0.1 prototype for migration but new projects write 1.0.0.

After asset approval, validate each `ai-video-reference-asset-package`; its `output` is a relative image path string. Create a bindings JSON with one entry per image to load, in load order: `asset_id`, `package`, `path`, `classification` (`human` or `normal`), and a concise `description`. One asset may have multiple approved panel crops. Run `scripts/bind_references.py --request ... --draft ... --bindings ... --output-dir ...`. It validates package approval, exact image membership/hash, asset coverage and shot IDs; then writes `seedance-with-assets.md`, `seedance-provider-ready.txt`, and `input-map.json`. The generated input map omits `model` so the current `seedancecli` router can choose from the full request. Add `--model <exact-id>` only when the user explicitly selected a model or the run is a controlled comparison. Review the final creative prompt for sensible reference use in each shot. Provider conversion is a mechanical step; final video submission belongs to `seedance-video`.
