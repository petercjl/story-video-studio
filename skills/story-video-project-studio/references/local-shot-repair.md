# Local shot repair

Use this branch when a generated segment is mostly usable and one or a few shots have a specific visual or action failure. Return to main-line video review after each repaired composite is inspected.

1. Watch the entire source with its sound. Identify the faulty action, surrounding story states, exact frame rate, and candidate cut boundaries. Find the first frame to replace and the first frame to retain after it; represent the source interval as `[start_frame, end_frame)`. Inspect frames on both sides and check for dialogue, music, effects and motion crossing the cuts. Decide whether a local replacement can communicate the corrected action without changing adjacent shots. When that is uncertain, use a wider shot boundary or revise the segment plan.
2. Present the user with the proposed interval, the visible action before and after it, the replacement action, expected candidate duration, audio treatment and continuity risk. The user reviews whether this shot should be replaced. An approved scope is required before a paid local generation; existing authorization for this specific repair remains valid.
3. Build the candidate prompt from the approved story, the segment's final prompt and approved identity/scene/prop assets. Describe the replacement action, its entry and exit states, camera, timing and sound needs. Use adjacent source frames as start/end anchors when the video provider supports them; otherwise bind the approved references and describe the transition. Save the prompt, reference paths and hashes, provider input map, dry-run hash, effective submit hash and task ID. Resume an existing task by ID. Preserve every downloaded candidate.
4. Watch the candidate and choose an in/out window containing exactly `end_frame - start_frame` frames. Select the window by visible entry and exit states; it may start after the candidate's first frame. Confirm common frame rate, dimensions and visual continuity. When the source audio already fits, use `python3 scripts/replace_video_shot.py --source SOURCE --replacement CANDIDATE --start-frame START --end-frame END --replacement-start-frame CANDIDATE_START --output NEW_COMPOSITE --manifest NEW_MANIFEST`. The script uses inclusive start/exclusive end windows, copies the original audio stream and verifies frame count and audio hash. If sound needs to change, prepare a separately reviewed audio edit and record its source and timing.
5. Inspect the complete composite, both joins at frame level and at playback speed, the replaced action, dialogue/sound alignment, final frame and technical metadata. Compare with the source. Record the source/candidate/composite hashes and splice manifest, QA result and user decision. Show the composite to the user; register it as accepted and current only after the user approves it. If a join fails, refine the candidate window or generation hypothesis and re-enter this branch within the authorized scope.

Use a new output path for every attempt. Never overwrite an approved original, provider candidate, prior preview or acceptance record. A visually corrected shot is insufficient when its audio or story action is inconsistent.
